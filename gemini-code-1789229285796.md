# System Design Document

## 1. Arsitektur Sistem & Teknologi
Sistem akan mengadopsi arsitektur *Client-Server* dengan pemisahan antara aplikasi web/mobile dan *backend* pemrosesan data.

* **Backend / API:** Menggunakan bahasa yang tangguh dalam komputasi matematis yang cepat dan konkurensi tinggi, yaitu **Golang** atau **Java (Spring Boot)**.
* **Frontend (Admin):** Framework SPA seperti React.js atau Vue.js untuk antarmuka dashboard yang dinamis.
* **Frontend (User):** PWA (Progressive Web App) dengan antarmuka yang dioptimalkan (Mobile First).
* **Database:** PostgreSQL untuk integritas relasional data keuangan.
* **Infrastruktur & Hosting:** Di-deploy menggunakan ekosistem **Google Cloud Platform (GCP)** (misalnya Cloud Run atau Compute Engine) dan di-routing ke subdomain produksi seperti `sistem.parrosz.xyz`.

## 2. Skema Database (ERD Utama)

| Nama Tabel | Kolom / Atribut Kunci | Relasi & Keterangan |
| :--- | :--- | :--- |
| `users` | `id_user` (PK), `nama`, `role`, `username`, `password` | `role` enum: admin, nego, sales, penagih. |
| `pesanan` | `id_pesanan` (PK), `nama_klien`, `nama_barang`, `total_harga`, `id_sales` (FK), `id_nego` (FK), `status` | Pusat data pesanan. |
| `pembayaran`| `id_bayar` (PK), `id_pesanan` (FK), `nominal`, `tanggal`, `id_penagih` (FK) | Riwayat angsuran. |
| `potongan` | `id_potongan` (PK), `id_user` (FK), `jenis`, `nominal`, `tanggal` | Data kasbon harian. |
| `komisi_log`| `id_log` (PK), `id_user` (FK), `jenis_komisi`, `nominal_masuk`, `id_referensi` | Tabel mutasi saldo (+/-) untuk riwayat transparan. |

## 3. Logika & Kalkulasi Sistem
Setiap ada *INSERT* baru pada tabel `pembayaran`, *Backend Service* akan langsung mengeksekusi perhitungan berikut:
1. **Hitung Rasio Uang Masuk:** `Rasio = Nominal Pembayaran / Total Harga Pesanan`.
2. **Distribusi Sales:** Tambahkan saldo ke akun Sales terkait sebesar `Rasio * 25.000`.
3. **Distribusi Nego:** Tambahkan saldo ke akun Nego terkait sebesar `Rasio * 10.000`.
4. **Distribusi Penagih:** Tambahkan saldo ke akun Penagih terkait sebesar nilai tetap `2.000`.

## 4. Desain Antarmuka (UI/UX)
### 4.1. Panel Web Admin (Desktop)
* **Tata Letak:** Sidebar statis di sebelah kiri (Menu: Dashboard, Pesanan Aktif, Data Setoran, Data Kasbon, Rekap Gaji).
* **Komponen:** Tabel lebar untuk melihat data (dilengkapi fitur *sorting* per kolom dan *search bar*), Form modal (*pop-up*) untuk input transaksi agar halaman tidak perlu memuat ulang.

### 4.2. Dashboard Pegawai (Mobile PWA)
* **Top Area:** *Hero section* menampilkan angka besar "Saldo Dapat Ditarik: Rp XXX.XXX".
* **Tab Navigasi Bawah (Bottom Bar):**
  * **Beranda:** Ringkasan dan tombol "Ajukan Pencairan".
  * **Pesanan Klien:** *List view* pelanggan yang masih berstatus cicilan (khusus untuk Nego/Sales).
  * **Riwayat:** *Timeline* kronologis masuknya komisi (hijau) dan potongan/kasbon (merah).
